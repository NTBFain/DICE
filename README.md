# DICE

DICE เป็นระบบจัดการงานวาดดิจิทัลสำหรับผู้ว่าจ้าง ศิลปิน และผู้ดูแล รวมการค้นหาศิลปิน ส่งรายละเอียดงาน ติดตามคิว สนทนา ขอแก้ไข ประมูล และรับไฟล์ไว้ในแอปเดียว

ระบบรองรับการรับชำระเงินพร้อมเพย์เข้าบัญชีกลางสองวิธี เมื่อเปิดใช้ Stripe Checkout ระบบจะสร้างคิวอาร์ตามยอดใบแจ้งหนี้และบันทึกการชำระเงินเมื่อได้รับการยืนยันจาก Stripe ส่วนการชำระผ่านคิวอาร์ของแพลตฟอร์มใช้การตรวจสลิปโดยศิลปินเจ้าของงานหรือผู้ดูแล การโอนเงินให้ศิลปินดำเนินการภายนอกระบบ

คำสั่งซื้อใหม่ตรึงอัตราค่าธรรมเนียม ค่าเริ่มต้นร้อยละ 5 งานเดิมเป็นร้อยละ 0 ผู้ว่าจ้างจ่ายยอดเดิม ผู้ดูแลบันทึกการโอนภายนอกให้ศิลปินเมื่องานเสร็จ ชำระครบ และมีเงินรับแพลตฟอร์มที่บันทึกชัดเจน เช่น ยอด 1,000 บาท ค่าธรรมเนียม 50 บาท สุทธิศิลปิน 950 บาท

## พร้อมเพย์และการจ่ายให้ศิลปิน

สำหรับการสาธิตการยืนยันยอดชำระอัตโนมัติ ให้ใช้ [คู่มือตั้งค่า Stripe Sandbox](docs/STRIPE_PROMPTPAY.md) สำหรับการตรวจสลิปและการบันทึกโอนเงินให้ศิลปิน ให้ใช้ [คู่มือตั้งค่าพร้อมเพย์ของแพลตฟอร์ม](docs/PROMPTPAY_SETUP.md)

## เริ่มสาธิตใน Windows PowerShell

ใช้ Git, uv, Python ตั้งแต่ 3.12 และ Node.js ตั้งแต่ 20.9.0 เส้นทางที่ตรวจใช้ Python 3.13.1 และ Node.js 24.21.0 อ่านคู่มือติดตั้งก่อนใช้ฐานข้อมูลที่มีข้อมูลจริง

จากโฟลเดอร์ราก ติดตั้งตามไฟล์ล็อกและสร้างความลับสุ่มหนึ่งครั้ง

```powershell
Set-Location backend
uv sync --locked --python 3.13
Set-Location ../frontend
npm ci
Set-Location ..
python scripts/setup_local.py --demo
```

PowerShell หน้าต่างแรก

```powershell
Set-Location D:/DICE/backend
uv run uvicorn main:app --host 127.0.0.1 --port 8000
```

หน้าต่างที่สอง

```powershell
Set-Location D:/DICE/frontend
npm run dev -- --hostname 127.0.0.1 --port 3000
```

เปิด `http://127.0.0.1:3000/th` ใช้ปุ่มบัญชีตัวอย่างเฉพาะเมื่อเปิด `DEMO_MODE` การหยุดใช้ Ctrl+C ในหน้าต่างที่ตนเปิด ไม่ปิดกระบวนการทั้งหมดตามหมายเลขพอร์ต สคริปต์เริ่มระบบรุ่นเก่าบางตัวมีพฤติกรรมปิดพอร์ต จึงใช้ขั้นตอน PowerShell ที่ตรวจแล้วเป็นหลัก

`backend/.env` เก็บความลับและฐานข้อมูลที่เลือก ไม่ส่งขึ้น Git ฐานเริ่มต้นคือ `backend/dice-local.db` และไฟล์อยู่ใน `backend/uploads` เมื่อต้องการบัญชีจริงให้ใช้ `--no-demo` และขั้นตอนสร้างผู้ดูแลคนแรกในคู่มือ

## โครงสร้างและการตรวจ

`frontend` ใช้ Next.js และ TypeScript, `backend` ใช้ FastAPI และ SQLModel, `test-suite` เก็บการตรวจแยกตามบทบาท, `docs/manuals` เก็บคู่มือและรุ่นส่งมอบ ขั้นงานหลักคือ `PENDING`, `ACCEPTED`, `SKETCHING`, `COLORING`, `COMPLETED` และ `CANCELLED`

```powershell
$dicePython = 'backend/.venv/Scripts/python.exe'
& $dicePython test-suite/run_checks.py --legacy
Set-Location frontend
npx tsc --noEmit
```

ตัวรันใช้ฐานข้อมูลและโฟลเดอร์ชั่วคราว ไม่ใช้เซิร์ฟเวอร์ที่กำลังให้บริการ ตรวจทีละกลุ่มเพื่อลดทรัพยากร การตรวจเบราว์เซอร์เป็นอีกส่วนหนึ่ง ดู [คำอธิบายชุดตรวจ](test-suite/README.md) และ [การตั้งค่าพร้อมเพย์](docs/PROMPTPAY_SETUP.md)

ขอบเขตรุ่นสาธิตนี้ไม่รวมการโอนเงินจริง การคืนเงินอัตโนมัติ การทดสอบโหลดจริง การรับรองหลายกระบวนการ หรือชุด Firefox/WebKit ครบทุกเส้นทาง
