# การตั้งค่าพร้อมเพย์และการบันทึกจ่ายให้ศิลปิน

DICE สร้างคิวอาร์พร้อมเพย์ตามยอดใบแจ้งหนี้เข้าบัญชีกลาง และให้ศิลปินเจ้าของงานหรือผู้ดูแลตรวจหลักฐานด้วยตนเอง ระบบไม่ตรวจยืนยันกับธนาคารและไม่สั่งโอนเงินให้ศิลปิน

## เตรียมระบบใน Windows PowerShell

ใช้ Python ตั้งแต่ 3.12, uv และ Node.js ตั้งแต่ 20.9.0 จากโฟลเดอร์โครงการ ติดตั้งตามไฟล์ล็อก:

```powershell
Set-Location backend
uv sync --locked --python 3.13
Set-Location ../frontend
npm ci
Set-Location ..
backend/.venv/Scripts/python.exe scripts/setup_local.py --no-demo
```

คำสั่งสุดท้ายสร้างความลับสุ่มใน `backend/.env` โดยไม่แสดงค่า ห้ามส่ง `.env`, ฐานข้อมูล หรือโฟลเดอร์ uploads ขึ้น Git หากต้องการบัญชีตัวอย่างเฉพาะชุดสาธิต ให้ใช้ `--demo` แทน `--no-demo` บัญชีตัวอย่างไม่ถูกสร้างเมื่อปิดโหมดสาธิต

ก่อนเริ่มกับข้อมูลเดิม ให้หยุดระบบแล้วสำรองฐานข้อมูลและ `backend/uploads` คู่กัน ตรวจ `DATABASE_URL` ใน `.env` ให้ตรงฐานข้อมูลที่ต้องการ ระบบสร้างตารางเงินใหม่และเพิ่มคอลัมน์เมื่อเริ่มทำงาน โดยงานเดิมมีอัตราค่าธรรมเนียมร้อยละ 0 ไม่สร้างเงินรับแพลตฟอร์มจากใบแจ้งหนี้เดิมที่อนุมัติแล้วโดยอัตโนมัติ

หากยังไม่มีผู้ดูแลในฐานข้อมูล ให้สร้างผู้ดูแลคนแรกผ่านคำสั่งต่อไปนี้จาก `backend` คำสั่งจะถามรหัสผ่านโดยไม่แสดงบนหน้าจอ และไม่ยกระดับบัญชีเดิม:

```powershell
Set-Location backend
uv run python ../scripts/create_admin.py
uv run uvicorn main:app --host 127.0.0.1 --port 8000
```

เปิด PowerShell อีกหน้าต่างจาก `frontend`:

```powershell
npm run dev -- --hostname 127.0.0.1 --port 3000
```

เข้า `http://127.0.0.1:3000/th` และหยุดแต่ละหน้าต่างด้วย Ctrl+C หากใช้พอร์ตแยก ให้ตั้ง `DICE_API_PROXY_TARGET` สำหรับพร็อกซี และ `NEXT_PUBLIC_API_URL` / `NEXT_PUBLIC_WS_URL` สำหรับการเชื่อมต่อฝั่งเบราว์เซอร์ก่อนเริ่ม frontend ค่าเริ่มต้นยังเป็น backend พอร์ต 8000

## เพิ่มคิวอาร์ของผู้รับเงิน

1. เข้าบัญชีผู้ดูแล แล้วเปิด `/th/dashboard/admin/payments` หรือ `/en/dashboard/admin/payments`
2. นำเข้าภาพคิวอาร์พร้อมเพย์ที่ผูกกับหมายเลขโทรศัพท์ไทย รองรับ PNG, JPG และ WebP ไม่เกิน 5 MB และ 10 ล้านพิกเซล ภาพต้องมีคิวอาร์ที่อ่านได้หนึ่งรายการ รุ่นนี้ไม่รองรับเลขบัตรประชาชน บัญชีธนาคาร หรือคิวอาร์ชำระบิล
3. ตรวจหมายเลขที่ระบบอ่าน และกรอกชื่อผู้รับให้ถูกต้อง การนำเข้ายังไม่บันทึกการตั้งค่า และภาพไม่ถูกเก็บไว้
4. กำหนดค่าธรรมเนียมสำหรับคำสั่งซื้อใหม่ ค่าเริ่มต้นคือร้อยละ 5 เปิดใช้พร้อมเพย์ แล้วบันทึก
5. ตรวจชื่อผู้รับและยอดที่แอปธนาคารแสดงทุกครั้งก่อนโอนเงินจริง ชื่อที่กรอกใน DICE ไม่ใช่ผลตรวจจากธนาคาร

## ขั้นตอนการชำระและจ่ายให้ศิลปิน

- ผู้ว่าจ้างเปิดใบแจ้งหนี้ที่ยังไม่ชำระและงานยังไม่ยกเลิก แล้วเลือกชำระด้วยพร้อมเพย์ ระบบสร้างคำแนะนำหนึ่งชุดต่อใบแจ้งหนี้ โดยตรึงผู้รับ ยอด และรุ่นการตั้งค่า
- ดาวน์โหลดหรือสแกนคิวอาร์ ตรวจยอด แล้วส่งสลิป JPG, PNG, WebP หรือ PDF ไม่เกิน 15 MB PDF ต้องอ่านได้ ไม่เข้ารหัส และมี 1–100 หน้า การสแกนหรือส่งสลิปยังไม่ทำให้ใบแจ้งหนี้ชำระแล้ว
- ศิลปินเจ้าของงานหรือผู้ดูแลตรวจและอนุมัติด้วยตนเอง การอนุมัติพร้อมเพย์ต้องมีหลักฐาน และบันทึกเงินรับ ผู้อนุมัติและเวลาในธุรกรรมเดียว การอนุมัติซ้ำไม่สร้างเงินรับซ้ำ
- เมื่อคำสั่งซื้อเสร็จ ชำระครบ มีเงินรับแพลตฟอร์มที่บันทึกชัดเจน และมียอดสุทธิมากกว่าศูนย์ ศิลปินเลือกทั้งคำสั่งซื้อเพื่อขอรับเงินได้โดยอัตโนมัติ รายการที่มีคำขอค้างอยู่หรือบันทึกจ่ายแล้วจะเลือกซ้ำไม่ได้ การส่งคำขอไม่ได้สั่งโอนเงิน
- ค่าธรรมเนียมตรึงเมื่อสร้างงาน คำนวณเป็นสตางค์และปัดครึ่งขึ้นต่อคำสั่งซื้อ เช่น เงินรับ 1,000 บาท อัตราร้อยละ 5 มีค่าธรรมเนียม 50 บาท และยอดสุทธิ 950 บาท
- ประวัติการจ่ายแก้ไขไม่ได้ งานที่บันทึกจ่ายแล้วไม่รับการเปลี่ยนแปลงการเงินหรือสถานะที่กระทบยอด การคืนเงินหรือปรับปรุงรายการต้องใช้กระบวนการในอนาคต

ใบแจ้งหนี้ที่ยกเลิกหรือชำระแล้วไม่สร้างคิวอาร์ใหม่ แต่ภาพคิวอาร์ที่ดาวน์โหลดไปแล้วเพิกถอนจากธนาคารไม่ได้ งานยกเลิกที่มีเงินรับยังแสดงไว้เพื่อจัดการด้วยตนเอง

## ศิลปินขอรับเงินและยืนยันการรับเงิน

1. เปิด **รายได้และสถิติ** ที่ `/th/dashboard/artist/analytics` แล้วไปที่ **ข้อมูลรับเงิน** กรอกชื่อเจ้าของบัญชีและหมายเลขโทรศัพท์ไทยที่ผูกพร้อมเพย์ของตนเอง รองรับการนำเข้าคิวอาร์ PNG/JPG/WebP ไม่เกิน 5 MB การนำเข้าอ่านหมายเลขเท่านั้น ไม่ยืนยันเจ้าของบัญชี และต้องกด **บันทึกข้อมูลรับเงิน**
2. ใน **คำสั่งซื้อที่ขอรับเงินได้** เลือกงานทั้งรายการ แล้วกด **ขอรับเงิน** ตรวจเงินรับ อัตราค่าธรรมเนียมที่ตรึงไว้ ยอดหัก ยอดสุทธิ และผู้รับ จากนั้นกด **ส่งคำขอรับเงิน** ข้อมูลผู้รับและยอดเงินของคำขอจะคงที่ แม้แก้ไขโปรไฟล์ในภายหลัง
3. สถานะ **ส่งคำขอแล้ว** หมายถึงยังไม่มีการโอนที่บันทึกไว้ ศิลปินยกเลิกได้เฉพาะก่อนผู้ดูแลรับดำเนินการ หากต้องการเปลี่ยนผู้รับให้ยกเลิกแล้วส่งคำขอใหม่ ประวัติเดิมยังคงอยู่
4. ผู้ดูแลเปิด `/th/dashboard/admin/payments` เลือก **ดูคำขอ** และ **รับดำเนินการ** ผู้ดูแลที่รับคำขอเท่านั้นจึงจะดูหรือดาวน์โหลดคิวอาร์พร้อมเพย์ตามยอดสุทธิของศิลปิน และบันทึกการโอนได้ ตรวจชื่อและยอดในแอปธนาคารก่อนโอนภายนอก DICE
5. หลังโอนจริง ผู้ดูแลเลือก **บันทึกการโอนภายนอก** ระบุเลขอ้างอิง แนบหลักฐาน PNG/JPG/WebP/PDF ไม่เกิน 15 MB และยืนยันว่าได้โอนแล้ว สถานะ **ผู้ดูแลบันทึกการโอนแล้ว** เป็นการบันทึกด้วยตนเอง ไม่ใช่การตรวจจากธนาคาร และยังไม่ใช่การยืนยันได้รับเงินของศิลปิน
6. ศิลปินเปิดคำขอจากประวัติหรือการแจ้งเตือน ตรวจหลักฐาน แล้วเลือก **ยืนยันได้รับเงิน** เมื่อได้รับเงินจริง หรือ **แจ้งปัญหา** พร้อมรายละเอียด ผู้ดูแลเพิ่มบันทึกการแก้ไขปัญหาได้ และศิลปินยืนยันรับเงินภายหลังได้ การยืนยันหรือแจ้งปัญหาไม่ทำให้โอนหรือจ่ายเงินซ้ำ

ผู้ดูแลปฏิเสธพร้อมเหตุผลได้เฉพาะคำขอที่ยังรอดำเนินการ ผู้ดูแลที่รับดำเนินการคืนคำขอได้เฉพาะเมื่อระบุเหตุผลและยืนยันว่าไม่ได้โอนเงิน ไม่มีการคืนคำขออัตโนมัติตามเวลา คิวอาร์ที่ดาวน์โหลดแล้วไม่สามารถเพิกถอนได้ จึงต้องประสานผู้ดูแลคนอื่นก่อนคืนคำขอ

ยอด **พร้อมจ่าย**, **ขอรับ / กำลังดำเนินการ** และ **บันทึกการจ่ายภายนอก** แสดงแยกกัน หน้าบันทึกจ่ายเดิมของผู้ดูแลยังใช้ได้กับงานที่ไม่ถูกสำรองโดยคำขอเท่านั้น การบันทึกโอนแล้วไม่สามารถเปลี่ยนผู้รับ ยอด หรือหลักฐานได้ รุ่นนี้ไม่รองรับการโอนเพิ่ม การคืนเงิน หรือการปรับยอดหลังจ่าย

เมื่อเริ่ม backend รุ่นนี้ ระบบเพิ่มตารางคำขอและข้อมูลรับเงินโดยไม่ลบข้อมูลเก่า ไม่สร้างคำขอย้อนหลัง และไม่ถือว่าการจ่ายเก่าถึงมือศิลปินแล้ว สำรองฐานข้อมูลและ uploads คู่กันก่อนอัปเกรดเสมอ

## ตรวจสอบก่อนใช้งาน

จากโฟลเดอร์ราก ใช้ฐานข้อมูลและไฟล์ชั่วคราวโดยตัวรันแยก ไม่ใช้ข้อมูลจริงและไม่มีการโอนเงินจริง:

```powershell
backend/.venv/Scripts/python.exe test-suite/run_checks.py --legacy
Set-Location frontend
npx tsc --noEmit
```

ขอบเขตรุ่นสาธิตไม่รวมการตรวจรายการธนาคารอัตโนมัติ การทดสอบโหลดจริง หรือการรับรองระบบหลายกระบวนการ
